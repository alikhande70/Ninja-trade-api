# طرح ربات خودمختار ۲۴ ساعته با بودجهٔ ۵۰۰ دلار

> تاریخ: ۲ مهر ۱۴۰۵ (24 September 2026) · جایگزین پیشنهاد اصلی گزارش امکان‌سنجی (`01-feasibility-report.md`) برای بودجهٔ فعلی
> ورودی‌های مالک پروژه: کل بودجه ۵۰۰ دلار، شامل سرمایهٔ معامله و همهٔ هزینه‌های سرور، API و داده؛ اجرای ۲۴ ساعته روی سرور ابری؛ ربات کاملاً خودمختار.

---

## ۱. تصمیم تازه: چرا مسیر عوض شد

مسیر پیشنهادی قبلی (قراردادهای آتی CME با دادهٔ Databento) حدود **۲۷۰ تا ۳۱۰ دلار در ماه** هزینهٔ ثابت داشت. با بودجهٔ ۵۰۰ دلاری، این هزینه کل سرمایه را در کمتر از دو ماه می‌خورد. به‌علاوه، برای نگه داشتن حتی یک قرارداد MES در طول شب، وجه تضمین لازم از ۵۰۰ دلار بیشتر است. پس این مسیر با بودجهٔ فعلی **ممکن نیست**.

**مسیر جدید: قراردادهای دائمی (Perpetual) بیت‌کوین و اتریوم در یک صرافی بزرگ رمزارز.**

| دلیل | توضیح |
|---|---|
| دادهٔ سطح دو رایگان | صرافی‌ها دفتر سفارش زنده را از طریق WebSocket عمومی و رایگان منتشر می‌کنند |
| حساب آزمایشی با دادهٔ واقعی | حساب Demo صرافی Bybit دادهٔ بازار واقعی دارد و فقط پول آن مجازی است |
| ۲۴ ساعت در ۷ روز | با خواست شما برای ربات همیشه‌روشن سازگار است |
| حداقل حجم کوچک | در Binance Futures، حداقل ارزش هر سفارش ۵ دلار است؛ با سرمایهٔ کم می‌توان اندازهٔ موقعیت را دقیق تنظیم کرد |
| محافظ قطع ارتباط | هر دو صرافی قابلیت «لغو خودکار سفارش‌ها در صورت قطع ارتباط» دارند |

**هزینه‌ای که این انتخاب دارد:** بازار رمزارز پراکنده‌تر است، ریسک خود صرافی وجود دارد و قوانین از کشوری به کشور دیگر فرق می‌کند. انتخاب نهایی صرافی **هنوز به محل اقامت شما بستگی دارد**. کد طوری نوشته می‌شود که عوض کردن صرافی فقط یک ماژول را تغییر دهد.

## ۲. تقسیم بودجهٔ ۵۰۰ دلار

### ۲-۱. هزینهٔ ماهانهٔ عملیات
| قلم | انتخاب | هزینهٔ ماهانه | وضعیت |
|---|---|---|---|
| سرور ابری | Hetzner CX23 (۲ هستهٔ پردازنده، ۴ گیگ حافظه)، دیتاسنتر آلمان یا سنگاپور | حدود ۶ یورو (۵٫۴۹ به‌علاوهٔ ۰٫۵۰ برای IPv4)، تقریباً ۷ دلار | قیمت پس از افزایش ژوئن ۲۰۲۶؛ پیش از خرید دوباره بررسی شود |
| دادهٔ سطح دو | WebSocket عمومی صرافی | ۰ | رسمی |
| دادهٔ تاریخی | ضبط توسط خود ربات، از روز اول | ۰ | — |
| API هوش مصنوعی | Claude Haiku 4.5 برای نظارت هر ۳۰ دقیقه، Sonnet 5 برای بازبینی روزانه | حدود ۹ تا ۱۳ دلار؛ **سقف سخت ۱۵ دلار** در کنسول Anthropic | برآورد |
| هشدارها | ربات تلگرام | ۰ | — |
| **جمع** | | **حدود ۲۰ دلار در ماه** | |

محاسبهٔ هزینهٔ هوش مصنوعی: نظارت ۴۸ بار در روز × (۴٬۰۰۰ توکن ورودی × ۱ دلار در میلیون + ۴۰۰ توکن خروجی × ۵ دلار در میلیون) ≈ ۰٫۲۹ دلار در روز ≈ ۸٫۶ دلار در ماه. بازبینی روزانه: ۵۰٬۰۰۰ توکن ورودی × ۲ دلار در میلیون + ۳٬۰۰۰ توکن خروجی × ۱۰ دلار در میلیون ≈ ۰٫۱۳ دلار در روز ≈ ۴ دلار در ماه.

### ۲-۲. تقسیم کل بودجه
| سهم | مبلغ | توضیح |
|---|---|---|
| عملیات در دورهٔ ساخت و معاملهٔ آزمایشی (حدود ۳ ماه) | ۶۰ دلار | در این دوره هیچ پولی به صرافی واریز نمی‌شود |
| ذخیرهٔ عملیات برای ۳ ماه اول معاملهٔ واقعی | ۶۰ دلار | |
| **سرمایهٔ معامله** | **۳۸۰ دلار** | فقط پس از تأیید صریح شما واریز می‌شود |

### ۲-۳. حقیقت اقتصادی این بودجه
با ۳۸۰ دلار سرمایه و ۲۰ دلار هزینهٔ ماهانه، ربات فقط برای **پوشش هزینه‌هایش** باید ماهانه حدود **۵٫۳٪ سود خالص** بسازد. این عدد برای هر استراتژی‌ای بسیار بالاست. اگر لایهٔ هوش مصنوعی ارزشی اضافه نکند و حذف شود، هزینه به حدود ۷ دلار و نقطهٔ سربه‌سر به حدود ۱٫۸٪ در ماه می‌رسد.

**نتیجه:** با این بودجه، هدف واقع‌بینانهٔ مرحلهٔ اول «درآمد» نیست. هدف، **اثبات یا رد وجود لبهٔ معاملاتی** با کمترین هزینه است. اگر لبه ثابت شد، تصمیم دربارهٔ افزایش سرمایه با شواهد گرفته می‌شود، نه با امید.

## ۳. معماری ربات خودمختار

```
 ┌────────────────────── Cloud server (Linux, Docker, 24/7) ───────────────────────┐
 │                                                                                  │
 │  [Recorder] ──► L2 + trades → compressed files (research history)               │
 │       │                                                                          │
 │  [Market Data] ──► local order book (snapshot + deltas, sequence check)         │
 │       │                                                                          │
 │  [Signals] ── deterministic features: imbalance, OFI, microprice, volatility    │
 │       │                                                                          │
 │  [AI Supervisor] ◄── every 30 min + on events ── Claude API (can only REDUCE risk)
 │       │                                                                          │
 │  [Risk Engine] ── hard limits, kill switch (final authority)                    │
 │       │                                                                          │
 │  [Execution] ──► exchange: orders + server-side stop + cancel-on-disconnect     │
 │       │                                                                          │
 │  [Journal DB] ── every decision, reason, fill, cost                             │
 │  [Watchdog] ── health checks, auto-restart, Telegram alerts, daily report       │
 └──────────────────────────────────────────────────────────────────────────────────┘
```

- **زبان و ابزار:** پایتون ۳.۱۲، asyncio برای WebSocket، SQLite و فایل‌های Parquet برای ذخیره، Docker و systemd برای اجرا و راه‌اندازی خودکار پس از خطا.
- **یک کد برای آزمون و اجرا:** لایه‌های سیگنال، ریسک و هوش مصنوعی در آزمون روی گذشته، معاملهٔ آزمایشی و معاملهٔ واقعی دقیقاً یک کد دارند. فقط منبع داده و درگاه اجرا عوض می‌شود.
- **حالت‌های اجرا:** `backtest` ← `paper` (حساب Demo) ← `live`. حالت `live` در پیکربندی قفل است و بدون تأیید شما باز نمی‌شود.

## ۴. خودمختاری: ربات چه کاری را بدون شما انجام می‌دهد و چه کاری را نه

### ۴-۱. کارهایی که کاملاً خودکار است
- دریافت داده، تحلیل، ورود، خروج، تعیین اندازهٔ موقعیت و معامله‌نکردن، به‌صورت ۲۴ ساعته.
- واکنش به خطا: اتصال دوباره، بازسازی دفتر سفارش، تطبیق وضعیت با صرافی، راه‌اندازی مجدد.
- توقف خودکار هنگام رسیدن به سقف‌های ضرر و ازسرگیری خودکار پس از پایان دورهٔ قفل روزانه.
- **به‌روزرسانی خودکار مدل با دروازهٔ کیفیت:** هر هفته مدل روی دادهٔ جدید دوباره آموزش می‌بیند. نسخهٔ جدید فقط وقتی جایگزین نسخهٔ فعلی می‌شود که (الف) در آزمون گام‌به‌گام رو به جلو از معیارها عبور کند و (ب) یک هفته در حالت سایه، یعنی تصمیم بدون معامله، از نسخهٔ فعلی بدتر نباشد. در غیر این صورت نسخهٔ فعلی می‌ماند.
- گزارش روزانه و هشدارهای فوری از طریق تلگرام. شما فقط در جریان قرار می‌گیرید و نیازی به اقدام نیست.

### ۴-۲. محدودیت‌هایی که هیچ بخش ربات، از جمله هوش مصنوعی، نمی‌تواند تغییر دهد
| قاعده | مقدار پیشنهادی برای ۳۸۰ دلار |
|---|---|
| حداکثر ریسک هر معامله | ۰٫۵٪ سرمایه (حدود ۱٫۹ دلار) |
| حداکثر اهرم مؤثر | ۲ برابر (موقعیت حداکثر حدود ۷۶۰ دلار) |
| حداکثر موقعیت هم‌زمان | ۱ در هر نماد، ۲ در کل |
| سقف ضرر روزانه | ۲٪ (حدود ۷٫۶ دلار) و قفل تا روز بعد |
| سقف ضرر هفتگی | ۵٪ و قفل تا هفتهٔ بعد، همراه با گزارش علت |
| **سقف ضرر کل** | **۲۰٪ (حدود ۷۶ دلار): توقف کامل تا تصمیم شما** |
| حداکثر تعداد معامله در روز | ۲۰ (جلوگیری از حلقهٔ معیوب) |
| دادهٔ کهنه (بیش از ۲ ثانیه بدون به‌روزرسانی) | معاملهٔ جدید ممنوع |
| انتقال یا برداشت وجه | **غیرممکن**: کلید API فقط مجوز معامله دارد و به IP سرور محدود است |
| تغییر سقف‌ها | فقط با تغییر دستی پیکربندی توسط شما |

### ۴-۳. رفتار هنگام قطع ارتباط و خرابی
| سناریو | رفتار |
|---|---|
| قطع اینترنت سرور | حد ضرر روی سرور صرافی فعال است؛ سفارش‌های باز با قابلیت «لغو هنگام قطع ارتباط» خودکار لغو می‌شوند |
| از کار افتادن برنامه | systemd آن را دوباره راه می‌اندازد؛ وضعیت از صرافی خوانده و تطبیق داده می‌شود؛ هیچ سفارش تکراری ارسال نمی‌شود |
| خاموشی کامل سرور | حد ضررهای سمت صرافی موقعیت را محافظت می‌کنند؛ پس از سه ضربان قلب ازدست‌رفته، هشدار «ربات خاموش است» از یک سرویس پایش رایگان خارجی ارسال می‌شود |
| خطا یا کندی API هوش مصنوعی | حالت پیش‌فرض ایمن: معاملهٔ جدید ممنوع، موقعیت‌های باز طبق قواعد عادی مدیریت می‌شوند |
| رفتار غیرعادی بازار (جهش نوسان، گسترش شدید فاصلهٔ قیمت) | توقف موقت ورود تا عادی شدن شرایط |
| خطای مکرر سفارش | پس از ۳ خطای پشت‌سرهم: توقف و هشدار |

## ۵. استراتژی: چه چیزی آزمایش می‌شود

- **نمادها:** BTCUSDT و ETHUSDT (قرارداد دائمی)، پرنقدینگی‌ترین بازارها.
- **افق زمانی:** ۱ تا ۳۰ دقیقه، نه میلی‌ثانیه. ربات ما در سرعت نمی‌تواند با شرکت‌های حرفه‌ای رقابت کند.
- **فرضیه‌های اولیه (هر کدام جداگانه آزمایش می‌شود):**
  1. عدم‌توازن جریان سفارش (OFI) و عمق دفتر، به‌عنوان تأییدکنندهٔ حرکت‌های کوتاه‌مدت.
  2. بازگشت قیمت پس از جذب سفارش‌های بزرگ.
  3. فیلتر رژیم بازار: معامله فقط وقتی نوسان در محدودهٔ مشخصی است.
- **اجرا:** تا جای ممکن سفارش محدود (Maker) برای کاهش کارمزد؛ شبیه‌ساز جایگاه در صف را مدل می‌کند.
- **هزینه‌ها در شبیه‌ساز:** کارمزد Taker و Maker طبق جدول صرافی (فرض محافظه‌کارانه: Taker برابر ۰٫۰۵۵٪)، لغزش قیمت، تأخیر ۲۰۰ میلی‌ثانیه، و هزینهٔ Funding هر ۸ ساعت.

## ۷. امنیت
- کلید API صرافی: فقط مجوز «معامله»، بدون مجوز برداشت، محدود به IP ثابت سرور.
- کلیدها و رمزها در فایل محیطی رمزگذاری‌شده روی سرور، هرگز در مخزن کد.
- ورود به سرور فقط با کلید SSH؛ دیوار آتش فقط درگاه SSH را باز نگه می‌دارد.
- سقف مصرف ماهانه در کنسول Anthropic روی ۱۵ دلار.
- موقعیت جغرافیایی سرور باید در کشوری باشد که صرافی آن را پشتیبانی می‌کند. ولی مجاز بودن حساب بر اساس **محل اقامت واقعی شما** تعیین می‌شود، نه محل سرور.

## ۸. سؤال‌های باز
1. **کشور محل اقامت (هنوز بی‌پاسخ):** انتخاب صرافی و قانونی بودن کل طرح به آن بستگی دارد. ساکنان ایران را هیچ‌کدام از صرافی‌های بزرگ و API شرکت Anthropic نمی‌پذیرند.
2. آیا برداشت من درست است که ۵۰۰ دلار **کل** بودجه، شامل هزینه‌ها، است؟
