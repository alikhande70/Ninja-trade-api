# طرح نهایی: ربات خودمختار روی MetaTrader 5 و کارگزار LiteFinance

> تاریخ: ۲ مهر ۱۴۰۵ (24 September 2026) · جایگزین طرح‌های `01` و `02` برای اجرا
> ورودی‌های مالک پروژه: کارگزار LiteFinance روی MT5؛ مدل زبانی آزاد است (رایگان یا پولی) و از طریق API استفاده می‌شود؛ سقف ۵۰۰ دلار کنار گذاشته شد و برآورد هزینه به عهدهٔ مسئول فنی است؛ حجم هر معامله باید خودکار از روی موجودی حساب تعیین شود.

---

## ۱. سه واقعیت مهم دربارهٔ این انتخاب

### ۱-۱. دادهٔ سطح دو واقعی در این کارگزار وجود ندارد
فارکس و طلای نقدی (XAUUSD) بازار متمرکز ندارند. در کارگزاری مثل LiteFinance، پنجرهٔ «عمق بازار» (DOM) در MT5، اگر اصلاً داده‌ای نشان دهد، **قیمت‌های خود کارگزار** را نمایش می‌دهد، نه دفتر سفارش واقعی بازار. مستندات رسمی MetaTrader همین را می‌گوید. پس هدف اولیه، یعنی ساخت ربات بر پایهٔ دفتر سفارش، با این کارگزار **به شکل واقعی قابل اجرا نیست**.

آنچه در دسترس است و استفاده می‌شود:
- **دادهٔ تیک:** تک‌تک تغییرات قیمت خرید و فروش. پهنای فاصلهٔ قیمت و سرعت رسیدن تیک‌ها جانشین تقریبی و ضعیف‌تری برای فعالیت بازار هستند.
- **حجم تیکی:** تعداد تغییرات قیمت، نه حجم واقعی معامله.
- **تاریخچهٔ تیک واقعی خود کارگزار** در Strategy Tester متاتریدر، که آزمون با اسپرد واقعی را ممکن می‌کند.

در فاز ۰ با تابع `MarketBookAdd` روی حساب دمو بررسی می‌کنم که LiteFinance اصلاً دادهٔ عمق ارائه می‌دهد یا نه، و اگر ارائه می‌دهد، کیفیتش چطور است.

### ۱-۲. ریسک خود کارگزار
شرکتی از LiteFinance که به مشتریان خارج از اروپا (از جمله ایران) خدمات می‌دهد، **LiteFinance Global LLC** است که در سنت‌وینسنت و گرنادین ثبت شده و **تحت نظارت هیچ نهاد مالی نیست**. شرکت اروپایی گروه (LiteForex Europe) مجوز CySEC دارد، ولی شامل این حساب‌ها نمی‌شود. پیامدها:
- اختلاف در برداشت یا بسته شدن حساب، مرجع شکایت مؤثری ندارد.
- کارگزار ممکن است طرف مقابل معاملهٔ شما باشد (مدل B-Book). یعنی سود شما ضرر اوست.
- **قاعدهٔ عملی:** هیچ‌وقت بیش از مبلغی که از دست دادن کاملش را تحمل می‌کنید در حساب نگه ندارید، و سودها را به‌طور دوره‌ای برداشت کنید.

نقاط مثبت: پذیرش مشتریان ایرانی به‌طور رسمی، حساب بدون سوآپ به‌صورت خودکار برای ایران، حساب سنت با حداقل واریز ۱۰ دلار، و محافظت از منفی شدن موجودی.

### ۱-۳. دسترسی به مدل‌های زبانی
اگر ساکن ایران هستید، Anthropic (Claude)، OpenAI و Google (Gemini) خدمات API را به ایران ارائه نمی‌دهند. استفاده از سرور خارجی این محدودیت را قانونی نمی‌کند، چون شرط این شرکت‌ها محل اقامت کاربر است. برای همین، لایهٔ هوش مصنوعی **مستقل از ارائه‌دهنده** طراحی می‌شود و سه حالت دارد (بخش ۴).

## ۲. معماری

```
 ┌──────────────── Windows VPS (24/7, near broker server) ────────────────┐
 │                                                                         │
 │  MetaTrader 5 terminal (LiteFinance)                                    │
 │  └── Expert Advisor (MQL5)  ◄── all fast and safety-critical logic      │
 │       • ticks, bars, spread monitor                                     │
 │       • signal engine (deterministic)                                   │
 │       • balance-based position sizing                                   │
 │       • risk engine + kill switch (final authority)                     │
 │       • execution: SL/TP on broker server, retries, state recovery      │
 │       • journal (CSV)                                                   │
 │            │  writes market_summary.json    ▲ reads ai_permission.json  │
 │            ▼  (Common Files folder)         │ (ignored if stale)        │
 │  AI sidecar (Python)  ── every 30 min + on events ──► LLM API / local   │
 │       • builds prompt, validates JSON reply, writes permission file     │
 │       • daily review, Telegram/e-mail reports                           │
 │  Watchdog: restarts terminal/sidecar, heartbeat to external monitor     │
 └─────────────────────────────────────────────────────────────────────────┘
```

**چرا این شکل:**
- هر چیزی که باید سریع و ایمن باشد **داخل خود اکسپرت (EA)** است. اگر برنامهٔ پایتون یا API هوش مصنوعی از کار بیفتد، EA همچنان حد ضرر، سقف ضرر و بستن موقعیت‌ها را کنترل می‌کند.
- ارتباط با هوش مصنوعی از طریق دو فایل ساده است. اگر فایل مجوز قدیمی‌تر از ۴۵ دقیقه یا خراب باشد، EA **معاملهٔ جدید باز نمی‌کند**.
- کتابخانهٔ رسمی پایتون MetaTrader5 فقط روی ویندوز کار می‌کند. به همین دلیل سرور ویندوزی انتخاب شد، نه لینوکس با Wine.
- آزمون روی گذشته با **Strategy Tester خود MT5** انجام می‌شود، در حالت «هر تیک بر اساس تیک‌های واقعی» و با کمیسیون واقعی. لایهٔ هوش مصنوعی فقط رو به جلو، روی حساب دمو، سنجیده می‌شود، چون مدل ممکن است اتفاقات گذشتهٔ بازار را از داده‌های آموزشی‌اش «بداند».

## ۳. تعیین حجم معامله از روی موجودی حساب

### ۳-۱. قاعده
در هر سیگنال، EA این محاسبه را انجام می‌دهد:

```
base        = min(Balance, Equity)            // conservative: floating loss counts
risk_pct    = 0.75% × dd_throttle × ai_multiplier   // ai_multiplier ∈ [0, 1]
risk_money  = base × risk_pct
loss_per_lot = (SL distance / tick_size) × tick_value + round-turn commission
lots        = floor_to_step(risk_money / loss_per_lot)
if lots < volume_min  → skip trade, log "account too small for this stop"
if margin(lots) > 30% of free margin → reduce lots / skip
```

- **پایهٔ محاسبه:** شما گفتید «بالانس». من کمترِ **بالانس و اکوئیتی** را مبنا گذاشتم. وقتی موقعیتی در ضرر باز است، بالانس از پولی که واقعاً دارید بیشتر است و مبنا قرار دادنش ریسک را بی‌صدا بالا می‌برد.
- **گرد کردن همیشه رو به پایین** است؛ گرد کردن رو به بالا ریسک را از سقف بیشتر می‌کند.
- **رشد خودکار:** با بزرگ‌تر شدن حساب، حجم معاملات به همان نسبت بزرگ می‌شود، و با کوچک‌تر شدنش کوچک.
- **ترمز افت سرمایه (`dd_throttle`):** اگر اکوئیتی ۱۰٪ زیر بالاترین مقدار قبلی باشد، ریسک هر معامله نصف می‌شود؛ اگر ۱۵٪ زیر آن باشد، به یک‌چهارم می‌رسد.
- **واریز و برداشت:** EA تراکنش‌های واریز و برداشت را تشخیص می‌دهد و مبنای محاسبهٔ افت سرمایه را اصلاح می‌کند، تا برداشت سود با ضرر اشتباه گرفته نشود.
- **ممنوع:** مارتینگل، شبکه‌ای (Grid)، میانگین‌کردن در ضرر، معامله بدون حد ضرر، و جابه‌جا کردن حد ضرر به سمت ضرر بیشتر.
- مشخصات نماد (tick size، tick value، حداقل حجم و گام حجم) **از خود کارگزار خوانده می‌شود**، نه از اعداد ثابت در کد.

## ۴. لایهٔ هوش مصنوعی مستقل از ارائه‌دهنده

**وظیفه:** همان نقش ناظر. هر ۳۰ دقیقه و هنگام رویدادهای مهم، خلاصه‌ای از وضعیت بازار و حساب دریافت می‌کند و پاسخی با قالب ثابت برمی‌گرداند:
`{"allow": true/false, "direction": "long|short|both|none", "size_mult": 0..1, "reason": "...", "expires_at": "..."}`

این پاسخ **فقط می‌تواند ریسک را کم کند.** پاسخ نامعتبر یا دیرهنگام یعنی «معاملهٔ جدید ممنوع». یک بازبینی روزانه هم معاملات و خطاها را تحلیل می‌کند.

**رابط واحد:** کد با قالب استاندارد «سازگار با OpenAI» (Chat Completions) نوشته می‌شود که تقریباً همهٔ ارائه‌دهندگان و سرورهای محلی از آن پشتیبانی می‌کنند. برای Claude از SDK رسمی Anthropic یک مبدل جدا نوشته می‌شود. تغییر مدل فقط تغییر پیکربندی است.

| حالت | گزینه | هزینهٔ ماهانه (۴۸ نظارت در روز + بازبینی روزانه) | ملاحظه |
|---|---|---|---|
| رایگان | مدل‌های رایگان OpenRouter | ۰ دلار (۵۰ درخواست در روز؛ با ۱۰ دلار شارژ یک‌باره، ۱٬۰۰۰ درخواست) | سقف ۵۰ درخواست برای ۴۸ نظارت کافی است ولی جای خطا ندارد؛ شرایط کشوری **تأییدنشده** |
| ارزان | DeepSeek V4.1 Flash برای نظارت و V4 Pro برای بازبینی | حدود ۵ دلار | شرایط دسترسی کشوری **تأییدنشده** |
| پولی باکیفیت | Claude Haiku 4.5 و Sonnet 5 | حدود ۱۳ دلار | ساکنان ایران را نمی‌پذیرد |
| مستقل از تحریم | مدل متن‌باز Qwen (مجوز Apache 2.0) با llama.cpp روی سرور خودمان | ۰ دلار API، ولی سرور بزرگ‌تری لازم است (حدود ۱۵ تا ۲۰ دلار اضافه) | روی پردازنده حدود ۴ تا ۱۰ توکن در ثانیه؛ برای پاسخ ۳۰۰ توکنی هر ۳۰ دقیقه کافی است |

**انتخاب:** در فاز ۳، از روی خود سرور، هر گزینه‌ای که **برای محل اقامت شما مجاز است** از نظر پایداری، کیفیت و هزینه آزموده می‌شود. پیش‌فرض طرح، حالت «مستقل از تحریم» به‌عنوان پشتیبان و یک API ارزان به‌عنوان گزینهٔ اصلی است.

**سنجش ارزش:** دو حساب دمو، یکی با هوش مصنوعی و یکی بدون آن، ۶ تا ۸ هفته به‌صورت موازی اجرا می‌شوند. اگر بهبود معنادار نبود، هوش مصنوعی از تصمیم معاملاتی حذف می‌شود و فقط گزارش روزانه را می‌نویسد.

برای اینکه هزینهٔ ثابت حدود ۳۰ دلار در ماه ارزش داشته باشد، ربات باید دست‌کم این مقدار سود خالص ماهانه بسازد:

**پیشنهاد مرحله‌ای سرمایه (هر مرحله با تأیید شما):**

3. افزایش سرمایه فقط بر اساس نتایج واقعی و با توجه به ریسک کارگزار (بخش ۱-۲).
